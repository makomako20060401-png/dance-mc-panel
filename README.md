# ダンスバトル MCパネル

ダンスバトルのMCが、実況・煽り・出演者の把握・時間管理をスマートフォン1台で行うためのコントロールパネルです。
ログインやサーバーは不要で、データは端末のブラウザ内に自動保存されます。

## 使い方（開発）

```bash
npm install
npm run dev        # http://localhost:5173 （--host 付きなので同じLANのスマホからも開けます）
npm test           # ロジックのユニットテスト（vitest）
npm run e2e        # ブラウザでの通し確認（要 Playwright、preview 起動中に実行。下記参照）
node e2e/offline-transfer.cjs   # オフライン起動・パソコン→スマホ受け渡しの確認
npm run build      # 型チェック + 本番ビルド（dist/）
npm run preview    # ビルド結果の確認
```

`dist/` は相対パスでビルドされるため、任意の静的ホスティング（GitHub Pages、Netlify など）のサブディレクトリにそのまま置けます。
`npm run build:single` は CSS・JS を埋め込んだ1枚の HTML（`dist-single/index.html`）を作ります（claude.ai の Artifact など、1ファイルで配る場合用。オフライン対応はしません）。

## オフラインで使う

`dist/` を HTTPS の静的ホスティング（GitHub Pages など）に置いて一度開くと、Service Worker がアプリの全ファイルを端末に保存し、以後は電波がなくても起動できます。
最初の画面に「✓ オフライン対応済み」と出れば準備完了です。会場に行く前に、機内モードで起動できることを確認しておくと安心です。

- Service Worker はビルド時に生成されます（`sw/sw.template.js` → `dist/sw.js`、`vite.config.ts` のプラグイン）。ビルドしたファイル一覧を埋め込み、初回表示で全ファイルを保存します。
- 画面は保存済みのものを即表示し、裏で最新版を取得します（会場の弱い電波で起動が待たされない）。アプリを更新した場合は、次回の起動で反映されます。
- 画面に戻るたびに更新を確認します。新しい版が届くと、最初の画面ではすぐに切り替わり、本番画面ではメニュー（☰）に赤い印と「新しい版に更新する」が出ます（入力内容・タイマーはそのまま）。最初の画面の下に今の版（日付とコミット）が表示されます。
- **iPhone の注意**: 「ホーム画面に追加」したアプリと Safari はデータの保存場所が別です。ホーム画面に追加してからは、ホーム画面のアイコンから使ってください（Safari で入力したデータはホーム画面版には出ません。移すときは下の転送コードを使います）。

## パソコンで入力してスマホで使う

サーバーは使わず、イベントを圧縮した**転送コード**（`DMCP1z.` で始まる文字列）で受け渡します（`src/transfer.ts`）。

1. パソコンで入力する。1 vs 1 は「対戦カードをまとめて入力」に1行1試合（`A vs B`、または Excel の2列を貼り付け）。サークル・チームの名前欄は、複数行を貼り付けると全員まとめて追加されます
2. 確認画面の「📲 この内容をスマホへ送る」（またはイベント一覧の 📲）で転送コードをコピー
3. LINE・メール・AirDrop などで自分のスマホに送る
4. スマホのアプリで「📥 受け取る」に貼り付け（前後に文章や改行が入っていても読み取れます）

同じイベントを送り直すと「上書き / 別に追加」を選べます。通常の Web サイトとして開いている場合は、QR コードとリンクでも送れます（リンクを開くとブラウザ側に取り込まれるため、iPhone のホーム画面版には転送コードを使ってください）。

## 技術構成

- React 19 + TypeScript + Vite
- 状態管理: React Context + immer（`src/store.tsx`）
- 保存: `localStorage`（キー `dance-mc-panel/v1`）。変更から250ms後、およびページを閉じる・裏に回るときに即時保存
- テスト: vitest（`src/model.test.ts`）、Playwright による通し確認（`e2e/smoke.cjs`）

### 通し確認（E2E）
`npm run build && npm run preview` を起動した状態で `npm run e2e` を実行します（Playwright は依存に含めていないため、初回は `npm i -D playwright && npx playwright install chromium`）。
タップ→NOW、長押し解除、警戒・時間切れ、名前挿入、スワイプ切替、再読み込み後の復元、イベント複製を確認し、
さらに 320px / iPhone SE / iPhone 14 の縦横それぞれで「画面全体がスクロールしない」「主要パネルが画面内」「高さ40px未満のボタンがない」を検査します。
スクリーンショットは `e2e/screenshots/` に出力されます。

```
src/
  types.ts          データ型（参加者とパフォーマンス履歴は分離）
  model.ts          ドメインロジック（選択・解除・試合切替・形式変換・入力チェック）
  time.ts           ストップウォッチとカウントダウン表示の計算
  storage.ts        保存・読込・JSONバックアップ
  store.tsx         アプリ状態と自動保存
  hooks/            長押し・スワイプ・画面スリープ防止・時刻更新
  components/
    StartScreen     新規作成 / 保存済みイベント再開 / バックアップ
    setup/          初期設定ウィザード（形式 → 共通設定 → 出演者 → 確認）
    live/           本番画面（試合ナビ / バトラー一覧 / MC原稿 / タイマー）
    common/         ダイアログ、時間入力、名前リスト編集
```

## 画面と操作

### 初期設定
1. 「新しいイベントを作成」または保存済みイベントを選んで再開
2. バトル形式（サークル / 1 vs 1 / 複数人 vs 複数人）
3. 共通設定（イベント名、試合数、個人タイマー、試合全体の制限時間、各警戒時間）
4. 試合ごとの出演者（追加・編集・削除・並べ替え、試合の追加・削除・並べ替え）
5. 内容確認 → 「本番画面へ」

### 本番画面
| 場所 | 内容 |
|---|---|
| 最上部 | 第X試合 / 全Y試合、対戦カード。◀▶ボタンまたは横スワイプで試合切替。中央タップで試合一覧からジャンプ。右端の「☰ 設定」から編集メニュー |
| 中央左 | バトラー一覧。タップ＝担当にする＋踊った印＋個人タイマー開始。踊った人は長押し（600ms）で印を解除。チーム形式では次に踊る側のチームに「NEXT」を表示 |
| 中央右 | MC原稿・メモ。左上「編集」→「保存」「キャンセル」。編集中は出演者名・チーム名のチップをタップしてカーソル位置に挿入できる。右上「拡大」（または見出しタップ）で全画面表示（文字サイズ変更可） |
| 最下部 | 個人タイマーと試合経過。▶/❚❚で開始・一時停止、↺は長押しでリセット |

## 設計判断（仕様の曖昧な点に対して採用した既定値）

**誤操作防止**
- 長押しは **600ms**。指が12px以上動いた場合（スクロール）やブラウザがタッチをキャンセルした場合は不成立。押している間は下端にバーが伸びて進捗を表示し、成立時に短く振動します。長押し成立後の click は無視するので、解除直後に誤って再選択されることはありません。
- **数人で踊り始めて1人が残るパターン**: 個人タイマーを手動で始めておけば、残った人の名前を押してもタイマーを初め直さずに数え続けます。
  - 試合の最初：そのまま ▶ → 残った人の名前
  - 2人目以降：前の人が終わったら ↺ を長押し（リセット）→ 踊り始めたら ▶ → 残った人の名前
  - 0 から ▶ を押すと「手動計測中」になり、前の人の NOW は外れます（踊った印は残ります）。途中で止めた時間からの再開（❚❚ → ▶）では担当者は変わりません
  - 担当者がいる状態から次の人の名前を押したときは、これまで通り初期値から始まります
- 選択は確認も通知も出さずに即開始します。間違えた場合は、その人を長押しで解除して正しい人をタップします。
- 踊った人・現在の担当者を通常タップしても何も変わらず、「長押しで解除」とトーストで案内します。
- キーボード操作では、長押しの代わりに Delete / Backspace キーで印の解除・タイマーリセットができます。
- タイマーのリセット（↺）は長押し。タップでは「長押ししてください」と案内するだけです。確認ダイアログを毎回出さずに、うっかりリセットを防ぎます。
- 本番中の「バトラー追加」は一覧の末尾に、名前ボタンと間隔を空けて点線枠で配置。1 vs 1 では2名固定のため出さず、設定メニューから編集します。
- 試合切替のスワイプは**最上部のナビゲーションのみ**で受け付けます。バトラー一覧や原稿は縦スクロールするため、そこで横スワイプを取ると誤切替が起きやすいからです。スワイプ後に指を離した位置のボタンが反応しないようにしています。
- 削除（バトラー・試合・イベント）、試合数を減らしてデータが消える場合、形式変更でデータが変わる場合、原稿編集の破棄は確認ダイアログを表示します。

**タイマー**
- タイマーは「開始時刻＋累積時間」で保持するため、表示の更新が止まっても時間はずれません。**ページの再読み込み中も動作中のタイマーは進み続けます**（会場ではバトルが続いているため）。
- 個人タイマーは制限時間ありならカウントダウン、0を過ぎても止めずに `+0:05` のように超過時間を表示します。警戒時間に入るとオレンジ＋「⚠ 残りわずか」、超過で赤＋「⏰ TIME UP」（色だけでなく文字でも区別）。
- 警戒時間 0分0秒 は「警告なし」として扱います（制限時間より小さい値であれば可）。
- 試合経過タイマーは、その試合で最初にバトラーをタップした時点で自動開始します。手動の開始・一時停止も可能です。
- 試合を切り替えると、切替前の試合の個人・試合タイマーをどちらも一時停止します。戻っても自動では再開しません（トーストで停止したことを通知）。
- 「イベント一覧へ」戻る時は全試合のタイマーを止めます。設定編集画面へ移る時はタイマーを止めません（編集中もバトルは進行しているため）。
- 対応端末では警戒時間・時間切れに入った瞬間にバイブレーション（設定でオフ可）。本番画面では Screen Wake Lock で画面消灯を防ぎます。

**データ**
- 参加者（`Battler`）とパフォーマンス履歴（`Performance`）を分けて保持。踊った印の解除は履歴の削除ではなく `voidedAt` による無効化で、ラウンド制（同じ人が複数回踊る）への拡張に備えています。
- 原稿の編集中の内容は試合ごとの下書きとして自動保存されます。別の試合に移動したり再読み込みしても下書きは残り、編集状態のまま戻れます。
- チーム形式では、チームごとに色を選べます（10色＋任意の色）。色はチーム見出しと名前ボタンの左端に付き、色の上の文字は自動で白／黒の読みやすい方になります。
- チームの上下（A/B）は、設定画面の「⇅ 上下を入れ替え」または本番メニューから入れ替えられます。名前・色・メンバーをまとめて入れ替えるので、踊った印やタイマーはそのまま残ります。
- 形式変更時の変換: → サークルは名前のある全員を残す、→ 1 vs 1 は先頭2名、→ チームは前半をA・後半をBに割り当て。
- 入力チェック: 名前・チーム名の空欄、1 vs 1 の人数、制限時間0秒、警戒時間 ≥ 制限時間はエラー（本番へ進めない）。サークルの0人・チームのメンバー0人・同名は警告のみ（本番中に追加できるため）。本番開始後に設定から戻る場合は、エラーがあっても確認の上で本番画面へ戻れます。
- イベント一覧の「⧉」で複製できます。出演者・タイマー設定・原稿を引き継ぎ、踊った印やタイマーはリセットされます（定期開催イベントの準備用）。
- 名前の追加は Enter で行いますが、日本語変換確定の Enter では追加しません。
- 端末の容量不足などで保存に失敗した場合は本番画面上部に警告を表示します。JSON への書き出し・読み込みでバックアップや端末移行ができます。

**レイアウト**
- 本番画面は画面全体をスクロールさせず、バトラー一覧と原稿はパネル内だけでスクロールします。
- 縦向き: ナビ / 中央2列 / タイマー2列。横向き（高さ600px以下）: ナビとタイマーを1行に圧縮し、バトラーは幅に応じて複数列に並べて、4パネルを一度に見渡せるようにしています。
- 幅360px未満の端末では原稿ヘッダーのボタンをアイコンのみにし、名前ボタンの余白を詰めて名前が途中で折り返されにくくしています。
- 白を基調にした見た目。文字・パネル・タイマーは小さめにして、情報量とすっきり感を優先しています（名前ボタンは高さ44px、横向きは40px）。
